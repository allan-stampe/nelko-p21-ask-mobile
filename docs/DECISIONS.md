# Technical decisions — v0.0.1

- **Separate repository:** Windows v1.0.1 is the read-only reference. Flutter 3.38.5 / Dart shared UI and protocol, Android API 26+, Java/Kotlin target 17. The committed Gradle wrapper/settings were generated with that exact Flutter version; the bootstrap can restore missing infrastructure without replacing authored native sources.
- **Native Classic SPP first:** a small Kotlin MethodChannel/EventChannel adapter avoids opaque Bluetooth dependencies and matches the desktop serial evidence. Android handles discovery, pairing and secure RFCOMM. Discovery is cancelled before connecting. Pure BLE devices are refused explicitly. Cached UUIDs are information, not proof of support.
- **Future portability:** the Dart platform interface separates discovery/connection/storage/export from shared state/protocol. iOS is future work requiring BLE feasibility and physical testing, not an assumed SPP port.
- **Concurrency:** one serialized native I/O executor; independent blocking receive thread. Connection epochs invalidate late results and stale receive events. Connection timeout closes the pending socket. One Dart transaction at a time prevents battery/cancel/print interleaving. A socket error can mean an unknown partial write; the UI must not claim successful printing.
- **Lifecycle:** reconnect only the remembered selected device, while foregrounded, with a five-second delay. Explicit disconnect stops retry for that session. Backgrounding cancels transactions/closes transport; resuming may reconnect. No foreground service, no automatic print replay.
- **Permissions:** API31+ SCAN/CONNECT runtime permissions, SCAN neverForLocation. Legacy Bluetooth/ADMIN and fine location restricted to API30 or below. No Internet, advertising, telemetry or background-location permission. The exported receiver is for Android system Bluetooth broadcasts; transport actions still check permissions and lifecycle.
- **Storage:** local SharedPreferences; no cloud or device-transfer backup. Diagnostic buffers are bounded; exported logs use SAF with local-only selection and require no general storage access. Logs can contain identifiers/data and should be reviewed before sharing.
- **Distribution:** universal release-mode APK with Android's generated debug/test signing configuration for this explicitly experimental release. No private signing material in source/artifacts. The certificate is public and included for audit. CI-generated keys are ephemeral, so upgrades across builds may require uninstalling and losing preferences. Establish a protected, owner-controlled stable release key before wider distribution.
- **Licensing:** MIT project, preserved Tyler C attribution for adapted Windows bitmap/protocol code. AGPL Python project is protocol research only; none of its implementation is copied or translated. Flutter framework/dependency notices are exposed in the application's license screen.
- **Verification boundary:** golden-byte, parser, state-machine and widget tests plus Android lint and APK manifest inspection cover automated behavior. Only the owner can confirm radio transport and printing using the physical printer. No advanced designer before that milestone.

## v0.0.2 text pipeline

The owner confirmed v0.0.1 SPP/reference printing on S22. The unchanged Kotlin transport now also carries a snapshotted Dart-rasterized text bitmap. Fixed 284×96 landscape layout, clockwise 96×284 printer rotation, bundled offline Go Regular, threshold 128 and exact packed-bit preview follow the Windows rendering convention. Overflow blocks printing. Details and remaining physical limits: [text pipeline](TEXT-PRINTING-v0.0.2.md). Current built APKs must pass API 31/36 emulator installation/start before a tagged release is published.
